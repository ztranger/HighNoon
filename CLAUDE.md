# High Noon — project guide

2D pixel-art Wild West **reaction-duel** game. Ship order: **Android → iOS → Web**. Unity **6000.3.21f1**, URP **2D Renderer**, new **Input System**. **The whole app is landscape** — the duel is a side-view showdown (the two gunslingers face off across the street, left vs right), and menus/map/story/tutorial are landscape too. `AppInit.Apply` locks `ScreenOrientation.LandscapeLeft` app-wide (`ProjectSettings` default orientation is LandscapeLeft too); every screen builds a **1920×1080** canvas via `UiCanvas.Overlay`. Portrait is intentionally dropped — landscape only.

Two players hold opposite ends of one phone; each taps their half (left / right of the street). On `BANG!` the first valid tap wins. Tapping *before* BANG is a false start (loss). Modes: **PvP** (built), **Coop 2v2** (built), **PvE campaign** (built — staged run with lives, solo 1v1 or 2-player 2v2, visual chapter map). **Android build/testing is the user's responsibility** — don't attempt APK builds here.

**Four duel types** (`DuelType`). PvP/Coop pick **Reaction** or **Timing** in the menu. A PvE stage picks its own type on `StageDef.Type` (`Campaign.ApplyToMatch` copies it; the menu toggle is ignored). **Reaction** = quick-draw on `BANG!`. **Timing** = one sweeping "sweet spot" bar. **Volley** = several opponents, one window at a time, repeat until their reserve is gone. **Sync** = two pistols and two bars; a green hand wounds its foe even if the other misses. Default for a stage that doesn't set `Type` is Timing. Black Jack (final boss) sets Reaction. The Saloon Singer, the Headliner, and the Chorus Girl set Sync. Canyon Ambush, the Payroll, the Dancer, and the Prima set Volley.

## Run it
Open `Assets/_Project/Scenes/MainMenu.unity` → Play. Pick players / difficulty → PLAY.
- Editor test controls: Player 1 = tap lower half or **S**; Player 2 = tap upper half or **W** (only when "2 Players"). Volley uses the left half / **S** only. Sync uses both halves at once: **S** locks the left bar, **W** locks the right (on device, left thumb and right thumb).
- Open `Duel.unity` directly to test a duel in isolation — uncheck **Use Match Settings** on the `Bootstrap` object to use its manual flags (`manualDuelType`, `manualVolleyOpponents`, `manualSyncOpponents`) instead of the menu selection. That sandbox shows REMATCH / MENU, not the campaign life flow.

## Architecture
Code-first: each scene has ONE bootstrap component that builds the camera, background, UI, audio and gameplay objects at runtime — minimal scene wiring, easy to drive via MCP. All gameplay is in namespace `HighNoon`, assembly `HighNoon` (`Assets/_Project/Scripts/HighNoon.asmdef`). Editor tools are `HighNoon.Editor`. Edit Mode tests are `HighNoon.Tests.Editor` and reference `HighNoon` — a test asmdef cannot see types that still live in predefined `Assembly-CSharp`. `DuelResolveTests` covers `DuelResolve` (see ARCHITECTURE_REVIEW §3.5).

Engineering backlog (fairness, leaks, BANG-window GC, save edge cases, what *not* to rewrite): [docs/ARCHITECTURE_REVIEW.md](docs/ARCHITECTURE_REVIEW.md). Agents should work that list before adding meta systems.

### Duel state machine (`DuelManager`)
`Intro (walk in) → Stance → Tension (hidden random countdown, players never see it) → Bang → Resolved → Result`.
Fires are compared by timestamp (`Time.realtimeSinceStartupAsDouble`); earliest valid tap wins. A tap before BANG = false start (that duelist loses their lane).

**Responsiveness (reaction game — latency matters):** each lane is **DECIDED** the instant its first valid post-BANG shot lands (`DecideLane`) — then `FireFxForNew` flashes only the winner; the opponent drops at once, blocked from firing (`Duelist.ShotFx`), so the loser never shoots. The round then keeps listening a short **grace (~0.6s)** so the slower player's OWN tap time is still captured, and a **finalize** step shows every reaction popup (winner's + loser's real ms). **A false start (tap during tension) settles that lane at once** — the jumper loses immediately, no waiting for the hidden timer (BANG is skipped for lanes already decided). In 2v2 the two lanes resolve on their own timing. Reaction popups are large + outlined for readability. (`AppInit.Apply()` sets `runInBackground` and `targetFrameRate = 60` with vSync off.)

**Lane-based / rounds:** duelists are paired by `Duelist.Lane` (Bottom vs Top). 1v1 = one lane. 2v2 (Coop) = lanes 0 & 1 resolved in parallel; if each side wins one lane, the two survivors get `Lane = 0` and fight a tie-break round until one side owns the match. Coop = 2 human players share the bottom (quadrant tap zones, editor keys A/D), two bots on top. **`StartDuel` resets every `Duelist.Lane` to its `HomeLane`** (the lane assigned in `DuelBootstrap`) so a prior match's tie-break `Lane=0` doesn't corrupt a rematch's pairing — without this, a rematch after a tie-break piled 3 duelists into one lane and 1 into the other, producing wrong deaths / a stray corpse ("3 dead" with no tie-break that round).

### Timing duel (sweet-spot bar) — `RunTimingMatch`
`StartDuel` branches on `Type`: `RunMatch` (Reaction), `RunTimingMatch` (Timing), `RunVolleyMatch` (Volley), or `RunSyncMatch` (Sync). The timing round reuses the intro/stance, shoot/death animations, tension audio, `ShowRoundResults`, `ShowFinal`/`ShowPveResult` — only the *decide* step differs. After stance, each human gets a `TimingBar` over their half (two humans on a side stack; a bot in PvP/Coop gets its own bar and self-aims by difficulty; **in PvE bots have no bar** — they're pure narrative). The pointer sweeps via `Mathf.PingPong`; a human's first tap in their zone **locks** their bar (shoot FX fires instantly); a bot locks at its self-aimed spot after a short delay; a human who never taps is force-locked to an obvious **miss** (they hesitated → they get shot). `Duelist.AimHit`/`AimError` record the result.
- **PvE** (`ResolveTimingPve`): the team must **all** land green — then the opponents drop; otherwise the opponent(s) shoot and the players who missed die. One round, no tie-break; routes straight to `ShowPveResult`.
- **PvP/Coop** (`ResolveTimingContest`): each lane is its own 1v1 — whoever stopped **closest to the green centre** wins their lane (smallest `AimError`; exact tie = nobody survives that lane), then reuses the survivor/tie-break loop and `ShowFinal`. 2v2 = two independent duels; split survivors (one per side) fight a tie-break round. (Intended/fair.)
- **Tuning** (`TimingTuning`, by `MatchSettings.BotDifficulty`): green half-width + sweep speed — Easy 0.130/0.75, Normal 0.085/1.0, Hard 0.055/1.4. Bot self-aim error is banded by difficulty (`BotAimError`). Accuracy popup: `PERFECT!`/`HIT`/`MISS`.

### Volley (several foes, one window at a time) — `RunVolleyMatch`
A PvE mission type, not a new `GameMode` and not a lane duel. `StageDef.Type = Volley` plus `StageDef.Opponents` (2–3). `Volley.FoeCount` clamps the count; 0 or 1 becomes 3, so the roster and the number of taps stay the same number. `DuelBootstrap.BuildVolley` puts one human on the left and that many foes on the right (front of the line is shot first). The 2-player toggle does not add a partner on a Volley stage — the status line reads VOLLEY.

`StartDuel` runs `RunVolleyMatch`, which reuses intro/stance, the Timing bar, tension audio, shoot/death, and `ShowPveResult`. It does not run the survivor/tie-break loop. After stance, each foe gets their own window (`Volley.BeatSeconds` = 4.5s, same green width and sweep speed as Timing for the stage difficulty). The bar is labeled with that foe's name. The player's first tap in the left half locks it (`HumanDuelInput` latches one shot, so the round calls `ResetInput` + `Arm` before every window; the pause between windows is deaf). Green removes `WeaponDef.Damage` from that foe. They drop when the reserve hits 0; if any is left, the same window opens again after `Volley.BetweenBeats` (0.45s). A miss or silence spends `StageDef.Strike` armor and the same foe stays up. Armor at 0 → standing foes shoot, the player drops, one campaign life is lost. Clearing every window is a win. Each green tap can set the best-aim record. A direct-scene Volley (no campaign) shows YOU WIN / YOU LOSE with REMATCH instead of lives and the map.

To add another Volley mission, set `Type` and `Opponents` on a `StageDef`. Do not add a `GameMode` value and do not pair these foes into lanes. PvP/Coop never play Volley or Sync: if `MatchSettings.Type` is still one of those after a campaign duel, `DuelBootstrap` falls back to Timing. The SETUP menu has no button for either.

### Sync (two bars, two hands) — `RunSyncMatch`
A PvE mission type: one gunslinger, two pistols, two bars at once. `StageDef.Opponents` is the whole line and must be even (`SyncRules.FoeCount`): **2** = one shot per pistol, **4** = two shots per pistol (each slider fires twice, once per foe on that hand). 0 becomes 2. An odd count rounds up, then clamps at 4. `DuelBootstrap.BuildSync` lines them up front to back. The left pistol (left half / **S**) owns the even slots — foe 1, then foe 3. The right pistol (right half / **W**) owns the odd slots — foe 2, then foe 4. The 2-player toggle does not add a partner; the status line reads SYNC. **The Saloon Singer** (chapter 1, Easy) is Sync × 2, one hit each. **The Headliner** (chapter 2, Normal) is Sync × 4 with reserve 3. **The Chorus Girl** (chapter 4, Hard) is Sync × 2, and a miss spends 2 armor.

Both bars of the current pair are on screen together. They share a green centre. The right pointer lags by `greenHalf × SyncRules.PhaseInGreen` (0.75), so both can be green at once, and that overlap shrinks on Hard (same `TimingTuning` as Timing). Hitting both in one pass is how you avoid two armor chips; a late second tap is still a legal shot. Each hand is its own `HumanDuelInput`, re-armed every pass; the duelist's single `Input` is not used. A tap fires that pistol immediately and shows HIT/MISS/PERFECT over its current foe. **A green tap removes `WeaponDef.Damage`**, and the foe drops at 0, even when the other hand misses. A miss or a silent timeout makes that foe fire at once and spends `StageDef.Strike` armor. Armor at 0 drops the player in that same moment; otherwise that foe stays and the pair repeats. Either way a lost duel costs one campaign life. Clearing every pair wins; the worst accuracy across the winning shots can set the best-aim record. A direct-scene Sync (`manualSyncOpponents`) shows YOU WIN / YOU LOSE with REMATCH.

To add another Sync mission, set `Type = Sync` and `Opponents` to 2 or 4. Volley stays the one-after-another line; Sync stays the two-pistol line.

### Arenas / locations
Random per duel (`Arenas.Pick`, avoids immediate repeat). Eleven arenas: Prairie, Dusty Town, Red Canyon, Boot Hill, Green Valley, Salt Flats, Painted Hills, Ghost Town, Midnight Mesa (night), Gallows Hill, Devil's Crossroads. Each is a procedural **side-view** (`BackgroundBuilder`): gradient **sky** → a low **sun/moon** disc sitting on the horizon behind the standoff → a distant **silhouette** (hills / buttes / rooftops / crosses / windmill by `ArenaStyle`) → noise **ground** below the horizon (`BackgroundBuilder.Horizon = -0.9`) → a soft **street** band → foreground **props**. A new arena = one `ArenaDef` (ground palette + optional `SkyTop`/`SkyHorizon`/`Sun`/`Hill` sky colours — derived from the ground if omitted — plus a reused `ArenaStyle` for props/silhouette; the name seeds a unique ground pattern). PvE will pin an arena per mission point via `MatchSettings.ForcedArena` — there is deliberately **no arena picker in the menu**.

### PvE campaign (`Campaign`) + mission map
Static run state (Core/`Campaign.cs`), split into **roads** (`Campaign.All`) and, within the selected road, **chapters**: `Chapters[]` of `ChapterDef {Title, Theme, Stages[]}`. The menu **PvE CAMPAIGN** button opens `CampaignSelectScreen` (not a duel). Road 0 is open; road N unlocks when road N−1 is cleared (`hn_cmp_cleared`). A locked row stays clickable and shows a toast: `Finish {previous title} first.` The live chain is **The Playbill** (the 13-node solo bill) → **Salt Debt** (1 chapter, 2 stages) → **Boot Hill Night** (1 chapter, 2 stages). `Campaign.Chapters` is the selected road. Run state = `Chapter`, `Stage`, `Lives` (start 3, shared team lives), saved with the road id (`hn_cmp_id`). **The Playbill** is 5 chapters / 13 stages, Easy→Hard: The Frontier · Dust & Bounty · Blood & Silver · Judgement Day · High Noon. `Type` defaults to Timing. Solo narrative bill: [docs/CAMPAIGN_STORY.md](docs/CAMPAIGN_STORY.md). Two-player bill (not built; do not fake it with the solo 2-player toggle): [docs/COOP_CAMPAIGN.md](docs/COOP_CAMPAIGN.md). **The Saloon Singer** (chapter 1) is Sync × 2. **Canyon Ambush** (chapter 1) is Volley × 3. **The Headliner** (chapter 2) is Sync × 4 with `Hp` 3. **The Payroll** (chapter 3) is Volley × 2 with `Hp` 3. **The Dancer** (chapter 4) is Volley × 3. **The Chorus Girl** (chapter 4) is Sync × 2 with `Strike` 2. **The Prima** (chapter 5, before the boss) is Volley × 2 with `Hp` 6. **Black Jack** (final boss) is Reaction and ignores `Hp` — set on that stage, not inferred from "last node". Each opponent has a distinct `CowboyLook` + intro banter; add content by extending the road's chapter array (any stage count). `AdvanceStage()` steps one node and wraps to the next chapter; `IsFinalStage` guards the win screen. Inserting a stage in the middle shifts saved `Stage` indexes; appending or retuning an existing node's `Type` does not. Inserting a road in the middle of `Campaign.All` changes who unlocks whom.

**Save / resume:** one in-progress run is persisted to PlayerPrefs — `StartRun`/`AdvanceStage`/`LoseLife`/`EndRun` all call `Campaign.Save()`; the menu calls `Campaign.LoadSavedRun()` on start. The campaign list shows **CONTINUE** on the saved road. A win `EndRun` clears the resumable save, bumps `Records.Completions`, and marks that road cleared so the next list entry unlocks. A loss clears the run and does not unlock the next road. Use these mutators (not raw `Campaign.Lives--` / `Active=false`) so state stays persisted. An old save with no `hn_cmp_id` resumes as The Playbill.

**Records** (Core/`Records.cs`, PlayerPrefs): fastest human quick-draw (`BestReactionMs`), best timing accuracy (`BestAccuracy`, 1 = dead centre), campaign `Completions`, furthest node. `DuelManager` reports a human winner's reaction / a human green hit each round; a new best fires `DuelHUD.ShowBanner("NEW BEST …")`. The menu shows a records line under the subtitle.

**Story screens:** one shared `Story` scene, driven by static `Story.Kind` (`ChapterIntro` / `Victory` / `Defeat`). Chapter intro shows "CHAPTER n/N" + title + `ChapterDef.Tagline` + BEGIN→Map; Victory/Defeat show flavor + PLAY AGAIN|TRY AGAIN (→ StartRun + ChapterIntro) and MENU.

**Flow:** Menu **PvE CAMPAIGN** → campaign list → a row calls `Campaign.Select` then either **Map** (CONTINUE) or `StartRun()` → **Story (chapter intro)**. BEGIN → **Map scene** (current chapter). `MapBootstrap` draws the chapter's nodes bottom→top (cleared=green, current=gold + cowboy token + pulse, locked=gray) with path lines; tapping the **current** node loads the **Duel**. `DuelBootstrap` (PvE branch) pins the stage arena, difficulty, and duel type via `Campaign.ApplyToMatch()` and builds from the Players toggle — **1 player = solo 1v1** ("YOU" vs the stage bot), **2 players = 2v2** (P1+P2 vs two stage bots, reusing lane/tiebreaker). A stage with `Type = Volley` or `Sync` ignores that toggle and builds one human vs the line (`Opponents`: Volley 2–3, repeat the window until `Hp` is gone; Sync even 2 or 4, shots per pistol = half, each shot removes weapon damage). Top status line (`DuelHUD.SetPveStatus`) shows chapter/stage/opponent/lives/SOLO|CO-OP|VOLLEY|SYNC. On result, `DuelManager.ShowPveResult` (player side = Bottom): **win mid-chapter** → result panel **MAP** (back to map); **win last stage of a chapter** → `AdvanceStage` + Story chapter-intro (next chapter); **win final stage** → Story **Victory**; **loss, lives left** → result panel **RETRY**/MAP; **loss, lives 0** → Story **Defeat**. `DuelHUD.ShowResult(message, label1, act1, label2, act2)` takes configurable buttons. Volley answers the same "did the player side win?" question; it does not grow a separate result path.

**Pre-duel dialogs:** `StageDef.Intro` is a `DialogLine[]` (`Speaker` + text). Tapping a map node sets `Campaign.ShowIntro`; `DuelBootstrap` (PvE) then plays a `DialogBox` (bottom panel, speaker portrait + name + line, tap to advance) with the duelists standing on the field, and starts the duel on finish with `manager.SkipFirstIntro=true` (skips the walk-in). `ShowIntro` is consumed so a RETRY doesn't replay it. ### Weapons
`Weapons.All` (Core/`Weapon.cs`) is the roster — each `WeaponDef` maps filename hints to shot clips in `Resources/Audio/Shots`. The menu has a **WEAPON** carousel (`< WEAPON: name >`, previews the shot on change); the pick is saved in `GameSettings.SelectedWeapon`. Each `Duelist.Weapon` is set in `DuelBootstrap` (human = `Weapons.Selected`, bot = `Weapons.Default` revolver); `DuelManager` fires `Audio.Gunshot(d.Weapon)` so each duelist sounds like their gun (`AudioBank.GunshotFor` picks a random matching variant). Current guns: Revolver 1 / Desert Eagle 2 / Shotgun 3 / Sniper 4 / Steampunk 2 — each with its own procedural pixel icon (`WeaponArt.For(index)`, shared 64×32 canvas) shown on the GUNS tab next to `DAMAGE`. Damage only matters in Volley and Sync. Reaction stays one BANG and one shot. A Timing PvE stage still resolves in one green and ignores `Hp`.

**Armor vs campaign lives.** `GameSettings.ArmorMax` (base 3, cap 8, key `hn_armor`) is the in-duel pool. Every Volley or Sync starts at that full value (`DuelHUD` reads `ARMOR n/max`). A miss spends `StageDef.Strike` (default 1). At 0 the standing foes shoot and the player drops; `ShowPveResult` then removes one campaign heart (`Campaign.Lives`, still 3 per run). The STATS tab **REINFORCE** button increments the saved max until the cap. There is no shop. A foe health bar is drawn only when `StageDef.Hp` is greater than the equipped gun's damage, so a Sniper (4) one-shots the Headliner (3) and shows no bar, while a Revolver (1) does. The Prima's reserve is 6, so no gun one-shots her. The Chorus Girl's `Strike` is 2. Sandbox Volley/Sync (direct Duel scene) uses the player's armor but leaves foes at 1 HP.

### Bots
Reaction is an **interval**, never a fixed time: `BotConfig.reactionMin..reactionMax`, sampled with `RollReaction()` at BANG. Difficulty (`MatchSettings.ApplyDifficulty`): Easy 0.45–0.75s, Normal 0.30–0.48s, Hard 0.18–0.30s. Bots fill empty top slots (single-player PvP now; Coop/PvE later).

## Conventions & gotchas
- **2D Renderer** → a **Global Light2D** must exist in any scene with SpriteRenderers, or they render black.
- **Audio** → every scene builds its camera in code and has **no `AudioListener`** of its own, so nothing is audible (editor or device) unless one is added. Each `SetupCamera` calls `AppInit.EnsureAudioListener(cam)` (adds one to the camera only if the scene has none). Audio is also globally gated by *Project Settings → Audio → Disable Unity Audio* (`AudioManager.m_DisableAudio`) — keep it off. All SFX are procedural (`ProcAudio`) and scale by `GameSettings.SfxVolume` (0 when muted). Menu has **SFX** / **VIBRATE** toggles (persisted).
- **Haptics** → `Haptics.Light/Medium/Heavy/Success` — Android only (system Vibrator, amplitude on API 26+; `Handheld.Vibrate` fallback keeps the VIBRATE permission). No-ops in editor / off-device / when disabled. Wired to shots (Light), deaths (Heavy), wins (Success). Feel is only testable on device.
- **`Application.runInBackground = true`** (set in both bootstraps + PlayerSettings) — without it Play mode freezes when the Unity window is unfocused (e.g. MCP-driven testing).
- **Landscape side-view duel.** The two gunslingers stand at world **x ≈ ±5, y ≈ 0** facing the centre; the right one is mirrored via `SpriteRenderer.flipX` (`DuelistView.Setup(..., rightSide)`). `DuelSide.Bottom` = **left** of the street, `DuelSide.Top` = **right** (the enum names are historical). Camera `orthographicSize = 4.4`. (No more 180° rotation — that was the old portrait layout.)
- **Team color** is baked into the cowboy sprite pixels; `SpriteRenderer.color` stays white.
- **uGUI Text**: always set `txt.text` explicitly; font = `Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")`. Decorative labels/popups must set `raycastTarget = false` (uGUI defaults it **true**) — otherwise a text drawn on top (e.g. a reaction/accuracy popup `SetAsLastSibling`) silently swallows clicks meant for the result buttons under it. `DuelHUD.MakeText` sets it false for all its text.
- **All UI is landscape**, `CanvasScaler` reference **1920×1080** — the duel HUD and every menu/map/story/tutorial screen (all via `UiCanvas.Overlay`; no portrait canvas anywhere). Reaction/accuracy popups pin **above each cowboy's head** (`DuelistView.PopupAnchor`); Timing bars sit on each player's **half** of the street (`DuelManager.BarPosition`, left = −470 / right = +470 x), upright (no 180° flip). Real sheet/rig duelists are scaled to `CowboyCatalog.FigureHeight` (3.2 world units); the procedural fallback cowboy is 24×32 @ PPU 24.
