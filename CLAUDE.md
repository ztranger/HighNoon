# High Noon — project guide

2D pixel-art Wild West **reaction-duel** game. Ship order: **Android → iOS → Web**. Unity **6000.3.21f1**, URP **2D Renderer**, new **Input System**, portrait orientation.

Two players hold opposite ends of one phone; each taps their half. On `BANG!` the first valid tap wins. Tapping *before* BANG is a false start (loss). Modes: **PvP** (built), **Coop 2v2** (built), **PvE campaign** (built — staged run with lives, solo 1v1 or 2-player 2v2; visual mission map TODO). **Android build/testing is the user's responsibility** — don't attempt APK builds here.

**Two duel types** (`DuelType`, chosen in the menu for PvP/Coop; the PvE campaign forces it per stage): **Reaction** = the classic quick-draw on `BANG!`; **Timing** = a sweeping "sweet spot" bar — tap while the pointer is in the green zone. In the PvE campaign every stage is a Timing test **except the final boss**, who is a real Reaction quick-draw.

## Run it
Open `Assets/_Project/Scenes/MainMenu.unity` → Play. Pick players / difficulty → PLAY.
- Editor test controls: Player 1 = tap lower half or **S**; Player 2 = tap upper half or **W** (only when "2 Players").
- Open `Duel.unity` directly to test a duel in isolation — uncheck **Use Match Settings** on the `Bootstrap` object to use its manual flags instead of the menu selection.

## Architecture
Code-first: each scene has ONE bootstrap component that builds the camera, background, UI, audio and gameplay objects at runtime — minimal scene wiring, easy to drive via MCP. All gameplay is in namespace `HighNoon`, default `Assembly-CSharp` (no asmdef yet).

`Assets/_Project/Scripts/`
- **Core/** — `DuelBootstrap` (assembles the duel scene), `DuelManager` (round state machine), `Duelist` (per-cowboy runtime state), `DuelEnums`, `MatchSettings` (static carrier from menu → duel), `GameSettings` (PlayerPrefs: SFX/haptics toggles + volume), `Records` (PlayerPrefs: best reaction / best accuracy / completions / furthest node), `Haptics` (Android vibration), `AppInit`.
- **Input/** — `IDuelInput`; `HumanDuelInput` (first touch/click in a screen zone, keyboard fallback, multi-touch aware); `BotDuelInput` (fires at BANG + random reaction).
- **Config/** — `DuelConfig`, `BotConfig` (ScriptableObjects; runtime instances created if none assigned).
- **View/** — `DuelistView` (poses via frame animation), `FrameAnimator`, `CowboyArt` (procedural pixel cowboy frames) driven by `CowboyLook` (hat style / chest accessory / facial hair / colors — gives each opponent a distinct look), `PlaceholderArt` + `PropArt` (background/prop sprites), `Arena` + `BackgroundBuilder` (procedural arenas), `WeaponArt` (procedural pixel weapon icons), `CameraShake`, `Tumbleweed`.
- **UI/** — `MainMenuBootstrap` (5-tab hub: STATS/records · GUNS/`WeaponArt` pistol + weapon carousel · HOME/idle hero via `UiSpriteAnim` + PvP/PvE · SETUP/full match-config test menu · SOUND/audio toggles + tutorial; bottom tab bar swaps full-screen panels), `UiSpriteAnim` (cycles a uGUI Image through sprites), `MapBootstrap` (PvE chapter map), `StoryBootstrap` (chapter/victory/defeat), `TutorialBootstrap` (interactive onboarding — teaches tap-your-half, wait-for-BANG/false-start, and the timing bar, using the real `HumanDuelInput`; UI-image cowboys so no Light2D needed), `DialogBox` (pre-duel banter), `IconArt` (app-icon generator), `DuelHUD` (BANG!, per-duelist reaction/accuracy popups pinned above each cowboy, full-screen flash, result panel with configurable buttons, PvE status line, builds `TimingBar`s).
- **View/**`TimingBar` — the Timing-duel sweet-spot bar (track + green zone + sweeping pointer), built in code on the HUD canvas; the top player's bar is rotated 180°.
- **Audio/** — `AudioBank` (maps each logical sound to a **folder** of variant clips under `Resources/Audio/…`, plays a random variant with no immediate repeat; procedural fallback if a folder is empty; `Shots/` is the weapon library → `GunshotDefault` picks one clean single shot for now), `ProcAudio` (procedural fallback generator), `DuelAudio` (duel SFX, pulls from `AudioBank`, volume from `GameSettings`), `Sfx` (scene-independent one-shot player for UI clicks / stingers — a persistent `DontDestroyOnLoad` `AudioSource`, also via `AudioBank`), `MusicPlayer` (persistent, two layers: MUSIC = shuffled playlist of `Resources/Audio/Ambient` in menu/map; AMBIENCE = looping wind from `Resources/Audio/Wind` inside a duel/tutorial while music pauses; both silent on Story; volume from `GameSettings.MusicEnabled`+`MasterVolume`; started by `AppInit.Apply` → `MusicPlayer.Ensure`). Real samples live in `Assets/_Project/Resources/Audio/{Shots,Bell,BodyFall,Hearthbeat,Win,Loose,Click,Ambient,Wind}` (see that folder's README). Story victory/defeat stings play on a **local** `AudioSource` (stop on scene exit, no bleed). Menu has **SFX / MUSIC / VIBE** toggles (persisted).

### Duel state machine (`DuelManager`)
`Intro (walk in) → Stance → Tension (hidden random countdown, players never see it) → Bang → Resolved → Result`.
Fires are compared by timestamp (`Time.realtimeSinceStartupAsDouble`); earliest valid tap wins. A tap before BANG = false start (that duelist loses their lane).

**Responsiveness (reaction game — latency matters):** the shoot flash + gunshot fire the **instant** a duelist taps (`FireFxForNew`, per frame). **Each lane is DECIDED independently** the moment its first valid post-BANG shot lands (`DecideLane`) — the shooter wins and the opponent drops at once, blocked from firing (`Duelist.ShotFx`), so the loser never shoots. The round then keeps listening a short **grace (~0.6s)** so the slower player's OWN tap time is still captured, and a **finalize** step shows every reaction popup (winner's + loser's real ms). **A false start (tap during tension) settles that lane at once** — the jumper loses immediately, no waiting for the hidden timer (BANG is skipped for lanes already decided). In 2v2 the two lanes resolve on their own timing. Reaction popups are large + outlined for readability. (`AppInit.Apply()` sets only `runInBackground`; frame rate left at platform default.)

**Lane-based / rounds:** duelists are paired by `Duelist.Lane` (Bottom vs Top). 1v1 = one lane. 2v2 (Coop) = lanes 0 & 1 resolved in parallel; if each side wins one lane, the two survivors get `Lane = 0` and fight a tie-break round until one side owns the match. Coop = 2 human players share the bottom (quadrant tap zones, editor keys A/D), two bots on top.

### Timing duel (sweet-spot bar) — `RunTimingMatch`
`StartDuel` branches on `Type`: `RunMatch` (Reaction) vs `RunTimingMatch` (Timing). The timing round reuses the intro/stance, shoot/death animations, tension audio, `ShowRoundResults`, `ShowFinal`/`ShowPveResult` — only the *decide* step differs. After stance, each human gets a `TimingBar` over their half (two humans on a side stack; a bot in PvP/Coop gets its own bar and self-aims by difficulty; **in PvE bots have no bar** — they're pure narrative). The pointer sweeps via `Mathf.PingPong`; a human's first tap in their zone **locks** their bar (shoot FX fires instantly); a bot locks at its self-aimed spot after a short delay; a human who never taps is force-locked to an obvious **miss** (they hesitated → they get shot). `Duelist.AimHit`/`AimError` record the result.
- **PvE** (`ResolveTimingPve`): the team must **all** land green — then the opponents drop; otherwise the opponent(s) shoot and the players who missed die. One round, no tie-break; routes straight to `ShowPveResult`.
- **PvP/Coop** (`ResolveTimingContest`): each lane goes to whoever stopped **closest to the green centre** (smallest `AimError`; exact tie = nobody survives that lane), then reuses the survivor/tie-break loop and `ShowFinal`.
- **Tuning** (`TimingTuning`, by `MatchSettings.BotDifficulty`): green half-width + sweep speed — Easy 0.130/0.75, Normal 0.085/1.0, Hard 0.055/1.4. Bot self-aim error is banded by difficulty (`BotAimError`). Accuracy popup: `PERFECT!`/`HIT`/`MISS`.

### Arenas / locations
Random per duel (`Arenas.Pick`, avoids immediate repeat). Eleven arenas: Prairie, Dusty Town, Red Canyon, Boot Hill, Green Valley, Salt Flats, Painted Hills, Ghost Town, Midnight Mesa (night), Gallows Hill, Devil's Crossroads. Each built procedurally (noise ground + props); a new arena = one `ArenaDef` (palette + a reused `ArenaStyle` for props; the name seeds a unique ground pattern). PvE will pin an arena per mission point via `MatchSettings.ForcedArena` — there is deliberately **no arena picker in the menu**.

### PvE campaign (`Campaign`) + mission map
Static run state (Core/`Campaign.cs`), split into **chapters**: `Chapters[]` of `ChapterDef {Title, Theme, Stages[]}`; `StageDef {Title, Arena, Difficulty}`; run state = `Chapter`, `Stage` (current node in the chapter), `Lives` (start 3, shared team lives). **5 chapters / 13 stages**, Easy→Hard: The Frontier · Dust & Bounty · Blood & Silver · Judgement Day · High Noon (final boss = Black Jack, a Reaction quick-draw). Each opponent has a distinct `CowboyLook` + intro banter; add content by extending this array (any stage count). `AdvanceStage()` steps one node and wraps to the next chapter; `IsFinalStage` guards the win screen.

**Save / resume:** the run is persisted to PlayerPrefs — `StartRun`/`AdvanceStage`/`LoseLife`/`EndRun` all call `Campaign.Save()`; the menu calls `Campaign.LoadSavedRun()` on start and shows a **CONTINUE CAMPAIGN** button (→ Map) when `HasSavedRun`. A win/loss `EndRun` clears the resumable save (a win also bumps `Records.Completions`). Use these mutators (not raw `Campaign.Lives--` / `Active=false`) so state stays persisted.

**Records** (Core/`Records.cs`, PlayerPrefs): fastest human quick-draw (`BestReactionMs`), best timing accuracy (`BestAccuracy`, 1 = dead centre), campaign `Completions`, furthest node. `DuelManager` reports a human winner's reaction / a human green hit each round; a new best fires `DuelHUD.ShowBanner("NEW BEST …")`. The menu shows a records line under the subtitle.

**Story screens:** one shared `Story` scene, driven by static `Story.Kind` (`ChapterIntro` / `Victory` / `Defeat`). Chapter intro shows "CHAPTER n/N" + title + `ChapterDef.Tagline` + BEGIN→Map; Victory/Defeat show flavor + PLAY AGAIN|TRY AGAIN (→ StartRun + ChapterIntro) and MENU.

**Flow:** Menu PLAY (PvE) → `Campaign.StartRun()` → **Story (chapter intro)** → BEGIN → **Map scene** (current chapter). `MapBootstrap` draws the chapter's nodes bottom→top (cleared=green, current=gold + cowboy token + pulse, locked=gray) with path lines; tapping the **current** node loads the **Duel**. `DuelBootstrap` (PvE branch) pins the stage arena/difficulty via `Campaign.ApplyToMatch()` and builds from the Players toggle — **1 player = solo 1v1** ("YOU" vs the stage bot), **2 players = 2v2** (P1+P2 vs two stage bots, reusing lane/tiebreaker). Top status line (`DuelHUD.SetPveStatus`) shows chapter/stage/opponent/lives/SOLO|CO-OP. On result, `DuelManager.ShowPveResult` (player side = Bottom): **win mid-chapter** → result panel **MAP** (back to map); **win last stage of a chapter** → `AdvanceStage` + Story chapter-intro (next chapter); **win final stage** → Story **Victory**; **loss, lives left** → result panel **RETRY**/MAP; **loss, lives 0** → Story **Defeat**. `DuelHUD.ShowResult(message, label1, act1, label2, act2)` takes configurable buttons.

**Pre-duel dialogs:** `StageDef.Intro` is a `DialogLine[]` (`Speaker` + text). Tapping a map node sets `Campaign.ShowIntro`; `DuelBootstrap` (PvE) then plays a `DialogBox` (bottom panel, speaker portrait + name + line, tap to advance) with the duelists standing on the field, and starts the duel on finish with `manager.SkipFirstIntro=true` (skips the walk-in). `ShowIntro` is consumed so a RETRY doesn't replay it. ### Weapons
`Weapons.All` (Core/`Weapon.cs`) is the roster — each `WeaponDef` maps filename hints to shot clips in `Resources/Audio/Shots`. The menu has a **WEAPON** carousel (`< WEAPON: name >`, previews the shot on change); the pick is saved in `GameSettings.SelectedWeapon`. Each `Duelist.Weapon` is set in `DuelBootstrap` (human = `Weapons.Selected`, bot = `Weapons.Default` revolver); `DuelManager` fires `Audio.Gunshot(d.Weapon)` so each duelist sounds like their gun (`AudioBank.GunshotFor` picks a random matching variant). Current guns: Revolver / Desert Eagle / Shotgun / Sniper / Steampunk. A weapon is sound-only for now — add stats/visuals to `WeaponDef` later.

### Bots
Reaction is an **interval**, never a fixed time: `BotConfig.reactionMin..reactionMax`, sampled with `RollReaction()` at BANG. Difficulty (`MatchSettings.ApplyDifficulty`): Easy 0.45–0.75s, Normal 0.30–0.48s, Hard 0.18–0.30s. Bots fill empty top slots (single-player PvP now; Coop/PvE later).

## Conventions & gotchas
- **2D Renderer** → a **Global Light2D** must exist in any scene with SpriteRenderers, or they render black.
- **Audio** → every scene builds its camera in code and has **no `AudioListener`** of its own, so nothing is audible (editor or device) unless one is added. Each `SetupCamera` calls `AppInit.EnsureAudioListener(cam)` (adds one to the camera only if the scene has none). Audio is also globally gated by *Project Settings → Audio → Disable Unity Audio* (`AudioManager.m_DisableAudio`) — keep it off. All SFX are procedural (`ProcAudio`) and scale by `GameSettings.SfxVolume` (0 when muted). Menu has **SFX** / **VIBRATE** toggles (persisted).
- **Haptics** → `Haptics.Light/Medium/Heavy/Success` — Android only (system Vibrator, amplitude on API 26+; `Handheld.Vibrate` fallback keeps the VIBRATE permission). No-ops in editor / off-device / when disabled. Wired to shots (Light), deaths (Heavy), wins (Success). Feel is only testable on device.
- **`Application.runInBackground = true`** (set in both bootstraps + PlayerSettings) — without it Play mode freezes when the Unity window is unfocused (e.g. MCP-driven testing).
- **Top duelist rotated 180°** (not Y-flip) so each player at opposite phone ends sees their cowboy upright.
- **Team color** is baked into the cowboy sprite pixels; `SpriteRenderer.color` stays white.
- **uGUI Text**: always set `txt.text` explicitly; font = `Resources.GetBuiltinResource<Font>("LegacyRuntime.ttf")`. Decorative labels/popups must set `raycastTarget = false` (uGUI defaults it **true**) — otherwise a text drawn on top (e.g. a reaction/accuracy popup `SetAsLastSibling`) silently swallows clicks meant for the result buttons under it. `DuelHUD.MakeText` sets it false for all its text.
- Portrait, reference resolution 1080×1920. Duelist scale 1.8, cowboy sprite 24×32 @ PPU 24.
- To eyeball procedural art: blit frames to a PNG contact sheet via `execute_code(safety_checks=false)` and open it.
